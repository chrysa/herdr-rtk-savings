## Purpose (FACT)

A single-file, stdlib-only Python daemon that publishes **RTK (Rust Token Killer)
token-savings gauges** onto every workspace row in the [Herdr](https://herdr.dev)
spaces sidebar. One row per workspace shows the savings rate (gauge/percent) and
tokens saved (number) over a configurable window, with a lifetime fallback.

Evidence: `README.md`, `monitor.py` module docstring, `herdr-plugin.toml`.

## Runtime shape (FACT)

- Distributed as a **Herdr plugin** (`herdr-plugin.toml`, id `chrysa.rtk-savings`,
  `min_herdr_version = 0.7.0`, `platforms = ["linux"]`; macOS declared untested).
- The whole implementation is `monitor.py` (~418 lines, stdlib only — no third-party
  runtime dependency; see `pyproject.toml` which declares only pytest/coverage/ruff tooling).
- Data source: RTK's own history DB at `~/.local/share/rtk/history.db`, opened
  **read-only** (`open_db`, `monitor.py`). No `rtk` subprocess per workspace, no network,
  no telemetry, no state beyond a pidfile (FACT — README "How it works" + module docstring).

## Command surface (FACT)

`monitor.py` dispatches via `main()` (line 408). Sub-commands from the module docstring:

| Command  | Role |
|----------|------|
| `ensure` | Start the background monitor if not already running; used by every plugin event hook. |
| `daemon` | The monitor loop itself (spawned by `ensure`). |
| `stop`   | Stop the monitor and clear the sidebar tokens. |
| `popup`  | Detail view rendered for `herdr plugin pane open`. |

The plugin manifest wires `ensure` to actions (`start`, `stop`, `savings`) and to the
events `workspace.created`, `pane.created`, `workspace.focused` (`herdr-plugin.toml`).

## Control flow (INFERENCE, from function names in `monitor.py`)

1. A herdr event (workspace/pane created, workspace focused) invokes `python3 monitor.py ensure`.
2. `cmd_ensure` (l.237) checks the pidfile lock (`daemon_alive` l.219 / `running_pid` l.212)
   and spawns the daemon if none is alive.
3. The daemon loop (`claim_pidfile` l.271, then a `publish_round` l.249 every `POLL_S=60s`):
   - lists panes via `herdr pane list` (`herdr_cli` l.149 / `herdr_json` l.153),
   - groups panes to workspace roots by majority cwd (`map_workspaces` l.160),
   - queries per-project savings from the read-only DB (`query_project` l.124,
     `stats_for` l.136) over the configured `window` (`window_start` l.101),
   - renders one of four token variants (`render` l.199, `compact` l.191) and publishes
     it with a TTL via `herdr workspace report-metadata` (`report_variant` l.172).
4. Unchanged tokens are re-reported every `REFRESH_S=600s`, well before `TTL_MS`
   (= `POLL_S * 20 * 1000` = 20 min) expires, so a dead monitor's rows self-clear.
5. `popup` path (`popup_line` l.356, `popup_project` l.364) renders the detail view.

## Colour / variant model (FACT)

Sidebar tokens cannot carry ANSI colour, so the plugin emits exactly one of four
variants per workspace — `rtk`, `rtk_low`, `rtk_hi`, `rtk_sum` (`VARIANTS`,
`monitor.py` l.44) — and the user's `~/.config/herdr/config.toml` styles each row.
Thresholds: `rtk_hi` at/above `HIGH_PCT`, `rtk_low` below `LOW_PCT`, else `rtk`;
`rtk_sum` is the lifetime-fallback row (`render`, `monitor.py`).

## Key resilience decisions (FACT — README "Gotchas", `monitor.py` `herdr_bin`)

- **Stale `HERDR_BIN_PATH`**: herdr sets it from `/proc/self/exe`, which reads
  `.../herdr (deleted)` after an in-place upgrade. `herdr_bin` (l.46) validates the path,
  strips the ` (deleted)` suffix, and falls back to `PATH` / usual install locations.
- **Lock-as-authority**: the pidfile *lock*, not the pid, decides liveness, because pids
  recycle fast enough that a stale pidfile can point at a live unrelated process
  (`daemon_alive` docstring, `monitor.py`).
